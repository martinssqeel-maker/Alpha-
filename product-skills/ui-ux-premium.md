Inspect the existing design tokens, component patterns, and real data/events before changing a screen. Build hierarchy with spacing, typography, alignment, and semantic color. Use the shared token system; do not add isolated palettes or decorative gradients to compensate for weak structure.

Design the complete interaction: loading, empty, hover, focus, disabled, success, error, cancellation, and approval where relevant. Every visible control must perform its stated action. Keep keyboard focus visible, label icon-only controls, respect reduced motion, and preserve readable contrast in every supported theme.

Keep interfaces calm and dense enough for sustained work. Use motion only to clarify a state change. Make destructive consequences explicit. Verify the running screen at realistic window sizes and inspect the result after the change; a polished mockup is not evidence that the implemented flow works.
