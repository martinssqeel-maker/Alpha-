Capabilities

What Alpha does today

Every item below is implemented in the shipped product. Nothing here is a roadmap, a mock-up, or a stock illustration — where a limit exists it is stated next to the feature.

◆

Local models first

Alpha talks to your own Ollama service: it discovers installed models, shows capability and size, streams real download progress, and can remove a model you no longer need. Nothing leaves your machine when you use a local model.

⇄

Cloud models without your own keys

Shared cloud inference is served from Alpha's own backend, so a new account can run an approved model immediately. The provider credential stays on the server — it is never shipped inside the desktop app and never reaches the browser.

◷

Usage you can actually see

Each request reserves allowance before it starts and settles to the provider's real token figure when the stream ends. Your account page shows the counter and the limit for the current period; a refused request tells you which limit it hit.

⛨

Permission-gated actions

File writes, deletions, commands, installs, network calls, commits and pushes are each governed by an allow / ask / deny level. A risky action opens an approval dialog and runs only if you accept it.

⌘

Confined to your project

File access stays inside the project folder you opened. Path traversal and symlink escapes are rejected, sensitive files are denied by default, and a cancelled generation stops the work rather than leaving it half-applied.

≡

Reviewable edits

Changes arrive as unified diffs with checkpoint and restore, atomic writes, and stale-file conflict detection — so you review a proposed change before it lands.

⑂

Git and GitHub

Status, diff, stage, commit, branch, pull and push, with no force-push path. Signing in with GitHub gives identity only; repository access is a separate authorization you grant deliberately.

▸

Streaming terminal

Run project commands with live output, real cancellation and a risk assessment before anything destructive is allowed to run.

✎

Attachments

Attach text, source files, images and PDFs to a prompt. PDF text extraction happens locally, and an uploaded document is treated as content to read — never as instructions that can change what the assistant is permitted to do.

Your own credentials

Bring your own provider when you want to

Alpha is not a walled garden. Any OpenAI-compatible endpoint can be configured — OpenAI, OpenRouter, Groq, DeepSeek, Together, LM Studio or your own host — and a configured provider is used for your requests.

▲

Local versus cloud is your choice

The active model is always named in the workspace. A local conversation is not silently sent to a cloud provider: cloud routing happens only for the cloud model you selected.

◈

Company-funded and self-funded are distinguished

Usage served by Alpha's shared credential and usage served by your own key are metered separately, so it is always clear which account paid for a request.

▤

Model catalogue with real status

A model is marked verified only after a request has actually completed against it. Until then it is labelled unverified, and a model whose plan does not include it is refused rather than quietly upgraded.

Operations

Built to be run, not just demonstrated

☰

Administration control center

A separate /admin area reports live accounts, plan mix, downloads, sessions, AI spend and audit history. Every action is authorized on the server by the database itself, and every change is written to an append-only audit log.

◎

Spend cannot run away quietly

An operator can pause shared cloud inference, disable a provider, cap a provider's monthly spend, or set a company budget — and the limits are enforced on the server as each request is claimed, not merely displayed.

⧗

Honest about failure

A rejected provider credential is reported as a configuration fault rather than a retryable error, a refused request names the limit it hit, and a metric that cannot be read shows as unavailable instead of as zero.
