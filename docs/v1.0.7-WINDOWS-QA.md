# v1.0.7 — Live Windows QA runbook

These four checks **cannot** run in Linux CI or in a headless container. Every
service they exercise needs a real Windows session: `powershell.exe`, the UI
Automation tree, Office COM, and a global hotkey. `tsc` and Vitest cover the pure
logic (`desktopInput.ts`, `hudGuard.ts`) and assert on the generated script text,
but nothing there proves a real `Notepad` got typed into.

Run this on Windows 10/11 x64. Record the evidence column as you go; a run is not
"passed" without it.

---

## 0. Preconditions

```powershell
node -v          # 22.x
npm ci
npm run typecheck
npm test         # expect 385 passed, 6 skipped
npx electron-vite build
```

Launch with a debugging port so the automated renderer check can attach:

```powershell
npx electron . --remote-debugging-port=9222
```

Then, in a second terminal:

```powershell
npm run smoke:desktop
```

That script asserts no overlay is covering the workspace, a real click changes
the view, and real keystrokes land in the prompt box. It is the only part of this
document that is automated — and it must be green before you trust anything else.

Before starting, open a scratch PowerShell and record the baseline so the
clipboard-restore and orphan-process checks have something to compare against:

```powershell
Set-Clipboard -Value 'ALPHA-QA-BASELINE'
Get-Clipboard
Get-Process powershell -ErrorAction SilentlyContinue | Measure-Object | % Count
```

## 1. Authorized roots & proof-of-work

**Goal:** a write outside any open project still lands, is confined to an allowed
root, and reports a *verified* byte count rather than a model claim.

1. Start Alpha with **no project open** (fresh profile).
2. Ask the agent: *"Create notes.txt in my Documents folder containing three
   lines of anything."*
3. In **Assist** mode expect an approval sheet first — `fileWrites` is `ask` in
   `src/shared/permissions.ts`. Approve it.

**Pass criteria**
- `%USERPROFILE%\Documents\notes.txt` exists and its size matches the badge.
- The Activity pill reads **Verified** with a real size (`CheckCircle2`), not
  **Unverified** (`ShieldAlert`) — see `ActivityTimeline.tsx:125-129`.
- `list_authorized_locations` returns `Documents` as an authorized root.
- The reported size equals `(Get-Item notes.txt).Length`. If they differ, the
  verification path is lying and this fails even though the file exists.

**Negative check (do this too):** ask the agent to write to
`C:\Windows\System32\drivers\etc\hosts`. Expect an outright refusal from the
`pathGuard` system-path blocklist — **no approval sheet**, no partial write.

| Field | Value |
|---|---|
| Badge state | |
| Reported / actual bytes | |
| Refusal shown for system path | yes / no |

## 2. App locator, Set-of-Mark, clipboard bridge

**Goal:** find an app, read its controls as a numbered map, act without moving
the cursor, and leave the user's clipboard exactly as you found it.

1. Ask: *"Open Notepad and type a paragraph about the weather."*
   - Expect `find_and_launch_app` → Notepad window.
2. Ask it to inspect the window.
   - `inspect_window_ui` must return a numbered map like
     `[1] Button "Close" (patterns: Invoke)`.
3. Ask for an annotated screenshot (`capture_window_screenshot` with
   `annotate: true`). The numbers on the image must match the numbers in the map
   — that is the whole point of Set-of-Mark.
4. Ask it to put text into the document. `interact_with_window_element` should
   prefer a cursor-free UIA pattern over synthetic mouse movement. **Your mouse
   must not jump.**
5. Clipboard integrity — the bridge must restore what was there before:

```powershell
# after the task completes
Get-Clipboard            # must still read: ALPHA-QA-BASELINE
```

6. Repeat step 4 with a payload that contains a single quote, a wildcard and a
   bracket — this is the v1.0.7 escaping fix under real load:

> `Bob's App [beta] 100% *draft* — don't strip ^v`

**Pass criteria**
- Notepad contains that exact string, quotes and asterisks intact.
- No PowerShell syntax error anywhere in the logs.
- `Get-Clipboard` still returns the baseline value.
- Temp file `%TEMP%\alpha-clip-*` (the clipboard bridge payload) is deleted.

| Field | Value |
|---|---|
| Numbered map looks like | |
| Mouse stayed still | yes / no |
| Clipboard restored | yes / no |
| Special characters intact | yes / no |

## 3. Office COM bridge (with RTF fallback)

**Goal:** a genuinely formatted `.docx`, produced through Word COM, degrading to
RTF when Office is absent.

1. Ask: *"Create a one-page status report in my Documents as a Word document,
   with a title, a heading and a three-item bullet list."*
2. Expect `create_or_edit_office_document` → `New-Object -ComObject Word.Application`
   (`desktopService.ts:794`).

**Pass criteria**
- The `.docx` opens in Word with real bold headings and a bullet list — not
  literal `**` markdown and not one unformatted paragraph.
- Word is **not** left running afterwards:
  `Get-Process WINWORD -ErrorAction SilentlyContinue` should return nothing.
- No orphan `powershell.exe` holding a COM handle.

**Fallback check:** on a machine without Office (or with the COM call forced to
fail), `desktopService.ts:334` writes `status-report.rtf` instead via
`renderRtf`. Expect a valid `.rtf` with `{\rtf1\ansi` as its first bytes, and a
message that says it fell back — not a silent success claiming `.docx`.

| Field | Value |
|---|---|
| Formatting correct | yes / no |
| WINWORD left running | yes / no |
| RTF fallback path | exercised / not exercised |

## 4. Global kill-switch (`Alt+Shift+Q`)

**Goal:** an in-flight multi-step task aborts immediately, everything it spawned
dies, and nothing is left half-owned.

1. Give the agent a deliberately long task — something that touches several
   tools in sequence, e.g. *"Read each file in my Documents one at a time and
   summarise them."*
2. While it is working, minimise Alpha so the floating HUD pill is visible.
3. Press **`Alt+Shift+Q`**.

**Pass criteria**
- The pill disappears immediately.
- A toast reports the agent stopped, with the cancelled state — the broadcast
  carries `EVENTS.agentStopped { at, cancelled }`.
- In-flight approvals are dismissed; the approval sheet does not stay stuck
  waiting on a task that no longer exists.
- No child processes survive the kill:

```powershell
Get-Process powershell -ErrorAction SilentlyContinue | Measure-Object | % Count
# must equal the baseline from step 0
```

- If the clipboard bridge was mid-flight, the clipboard is restored, not left
  holding the bridge payload.
- The app stays usable: send a new prompt afterwards and confirm it runs. The
  kill-switch must not require a restart.

| Field | Value |
|---|---|
| Pill hidden | yes / no |
| Process count before / after | |
| App usable after kill | yes / no |

## 6. Where v1.0.7 actually stands

`v1.0.7` was published on 2026-10-22 by `.github/workflows/release.yml` (tag
push), not by hand: the tag run compiled the app, built the NSIS installer on a
Windows runner, and attached

- `Alpha.AI.Workspace-Setup-1.0.7.exe`
- `Alpha.AI.Workspace-Setup-1.0.7.exe.blockmap`
- `latest.yml`

then marked the release `latest`. Note the asset uses dots where 1.0.5/1.0.6
used hyphens — electron-builder folds the space in `productName` — but
`latest.yml` names the same file, so the updater resolves it consistently.

That means the website already resolves `1.0.7` with no code change, and any
installed 1.0.6 will be offered it.

**Still outstanding, and the reason the table above still matters:**

```powershell
npm run release:register        # with DATABASE_URL
```

Publishing to GitHub Releases does **not** write `public.releases`, so the gated
`GET /downloads/latest` still serves **1.0.6** to signed-in users until this
runs. The installer is also **unsigned** (no signing certificate in CI), so
first install triggers a SmartScreen warning.

For future releases, push a `vX.Y.Z` tag whose version matches `package.json`
and `APP_VERSION` — the workflow refuses the build if they disagree:

```powershell
git tag -a v1.0.8 -m "Alpha v1.0.8"
git push origin v1.0.8
```
